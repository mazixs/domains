# Domains

Список доменов для выборочной маршрутизации через VPN или прокси и инструмент для работы с ним. Подходит для встроенных DNS-маршрутов Keenetic (KeeneticOS 5.0+), [kvas](https://github.com/qzeleza/kvas) и других решений, которые принимают список доменов по одному в строке. Инструмент проверяет список, собирает компактную версию, ищет мертвые домены и генерирует команды для CLI Keenetic.

## Быстрый старт

Самый короткий путь - [uv](https://docs.astral.sh/uv/): он сам поставит зависимости во временное окружение.

```bash
uv run domains.py                  # сводка: список, сборка, последняя проверка
```

Или обычный venv:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # или pip install -e . - появится команда domains
```

Повседневные команды:

```bash
python domains.py                           # сводка и подсказки
python domains.py add claude.ai             # добавить домен: раздел подберется сам, маршруты пересоберутся
python domains.py rm old.example.com        # удалить домен
python domains.py where https://claude.ai/new   # чем покрыт домен и пойдет ли он через VPN
python domains.py check                     # найти мертвые домены (DNS, DoH, RDAP, HTTPS)
python domains.py check --html report.html  # то же с HTML-отчетом
python domains.py keenetic -i Wireguard0 > keenetic.txt   # команды для Keenetic
```

Нужен Python 3.10+. Работает на Windows, Linux и macOS.

## Файлы

| Файл | Что это |
|------|---------|
| `list.txt` | Исходный список: все домены и поддомены по разделам `## Сервис`. Редактируется руками. |
| `list_2nd_level.txt` | Собранный компактный список для маршрутизации. Генерируется командой `build`, руками не правится. |
| `shared_infra.txt` | Зоны общей инфраструктуры (CDN, облака, SaaS), которые нельзя схлопывать до 2-го уровня. |
| `domains.py` | Точка входа CLI. |
| `domainlist/` | Код: `names` (нормализация и валидация), `listfile` (разбор файла), `lint`, `build`, `edit` (add/rm/where), `checker` и каналы проверки `resolver`, `doh`, `rdap`, `probe`, `history`, `report` (HTML), `cli`. |
| `tests/` | Тесты pytest, работают без сети. |
| `.domains-state.json` | История проверок (создается `check`, в git не попадает). |
| `.cache/` | Кэш списка RDAP-серверов IANA (в git не попадает). |

### Формат list.txt

```
# Комментарий
## Название раздела

claude.ai
api.claude.ai   # комментарий в строке
# old.claude.ai - закомментированный домен игнорируется
```

- Раздел начинается с `## `. Остальные строки, начинающиеся с `#`, считаются комментариями.
- Одного домена достаточно для всех его поддоменов: и Keenetic, и kvas сами включают `*.claude.ai` для `claude.ai`.
- Домен может встречаться в нескольких разделах. Это не ошибка, `lint` покажет такие случаи в режиме `-v`.

## Где использовать

`list_2nd_level.txt` рассчитан на системы, которые по одному домену сами включают все его поддомены. Формат файла: один домен в строке, заголовки разделов оформлены как комментарии `#`, окончания строк LF, без BOM.

| Решение | Как подключить |
|---------|----------------|
| Keenetic, встроенные DNS-маршруты | `python domains.py keenetic -i <интерфейс>`, затем вставить команды в CLI роутера. Подробнее в разделе [keenetic](#keenetic---команды-для-роутера). |
| kvas | Скопировать `list_2nd_level.txt` на роутер и выполнить `kvas import list_2nd_level.txt`. Импорт добавляет домены к текущему списку, а не заменяет его: чтобы начать с чистого списка, сначала выполните `kvas clear`. |
| Другие решения | Подойдет любое решение, которое читает домен в строке и сам включает поддомены. Если поддомены нужно перечислять явно, используйте `list.txt`: в нем есть все известные поддомены. |

Лимит 300 записей относится только к встроенным DNS-маршрутам Keenetic.

Файлы `*.txt` хранятся в git с окончаниями LF (`.gitattributes`), потому что `kvas import` не понимает CRLF. `build --check` сравнивает файлы побайтово и считает список с CRLF устаревшим.

## Команды

Без аргументов `python domains.py` показывает сводку: сколько доменов и разделов, чисто ли по `lint`, актуален ли `list_2nd_level.txt`, когда была последняя проверка и какие домены в ней не работали.

### add, rm, where - правка списка без редактора

```bash
python domains.py add status.example.com              # раздел подбирается по родственным доменам
python domains.py add new.example.org -s "Другие"      # в раздел по части названия
python domains.py add api.example.org --new "Example"  # в новый раздел в конце файла
python domains.py rm old.example.com                  # удалить домен
python domains.py rm example.com --sub                # вместе со всеми поддоменами
python domains.py where https://music.example.com/x   # покрыт ли домен и через какой маршрут
```

`add` принимает и URL, и домены с мусором: `https://claude.ai/new` превратится в `claude.ai`. Перед добавлением:
- уже существующие домены пропускаются, а если домен покрыт родителем или уже маршрутизируется, `add` скажет об этом (добавить все равно: `--force`);
- выполняется быстрая DNS-проверка: несуществующий домен (обычно опечатка) не добавляется без `--force`, проверку можно отключить `--no-check`;
- раздел выбирается по родственным доменам (тот же зарегистрированный домен или родитель). Для общих зон вроде `b-cdn.net` родство не угадывается, ведь там живут чужие сервисы. Если угадать не удалось, в терминале появится список разделов, а без терминала нужно указать `-s` или `--new`.

После `add` и `rm` программа показывает, какие маршруты появились и исчезли, и пересобирает `list_2nd_level.txt`, если он лежит рядом со списком. Если удаленный домен по-прежнему идет через VPN (например, его покрывает соседняя запись, схлопнутая до того же домена), `rm` об этом предупредит. Опустевший раздел удаляется вместе с заголовком.

`where` завершается с кодом 1, если хотя бы один домен не маршрутизируется. Для имен в общих зонах (CDN, облака) подсказывает добавлять полное имя.

### lint - проверка без сети

```bash
python domains.py lint           # отчет
python domains.py lint -v        # с информационными сообщениями
python domains.py lint --fix     # исправить то, что можно исправить автоматически
python domains.py lint --strict  # предупреждения считаются ошибками (для CI)
```

**Ошибки** (домен не попадет в сборку):
- IP-адрес или CIDR вместо домена;
- пробел внутри, `*` в середине, пустая метка (`a..com`);
- длина имени больше 253 символов или метки больше 63;
- недопустимые символы, дефис в начале или конце метки;
- неизвестная или числовая зона, голая публичная зона (`com`, `co.uk`);
- склеенные домены вида `ctobsnssdk.comwww.trae.ai` (частая ошибка при копировании).

**Исправляется через `--fix`:**
- URL вместо домена (`https://claude.ai/path` -> `claude.ai`), порт, `*.` в начале, точка в начале или конце, регистр;
- IDN переводится в punycode (`пример.рф` -> `xn--e1afmkfd.xn--p1ai`);
- повтор домена в том же разделе, лишние пробелы.

Комментарии и структура файла сохраняются. Окончания строк (CRLF или LF) не меняются, BOM удаляется.

### build - сборка компактного списка

```bash
python domains.py build          # записать list_2nd_level.txt
python domains.py build -v       # показать, какие домены оставлены целиком
python domains.py build --check  # только проверить актуальность (код 1, если устарел)
```

Правила сборки:

1. Поддомен схлопывается до зарегистрированного домена по [Public Suffix List](https://publicsuffix.org/): `api.console.anthropic.com` -> `anthropic.com`, `x.marscode.com.cn` -> `marscode.com.cn`.
2. Домены в зонах из private-раздела PSL (`github.io`, `cloudfront.net`, `blob.core.windows.net`, `cdn.cloudflare.net` и т.д.) и из `shared_infra.txt` остаются целиком. Иначе через VPN пошел бы трафик всех клиентов CDN.
3. Если голая зона указана в `list.txt` явно (например, `sentry.io`), она перекрывает свои поддомены.
4. Домен, у которого в итоговом списке уже есть родитель, удаляется, потому что уже покрыт родителем.
5. Домен попадает в тот раздел, где он указан буквально. Если такого раздела нет, он попадает туда, где встретился впервые.

PSL берется из снимка, встроенного в `tldextract`. Поэтому сборка детерминирована и не ходит в сеть: одинаковый `list.txt` всегда дает одинаковый результат.

Если в `list.txt` есть ошибки, `build` не запускается. Если доменов больше 300, `build` предупредит о лимите встроенных DNS-маршрутов Keenetic.

### check - поиск мертвых доменов

```bash
python domains.py check                      # весь list.txt
python domains.py check -s claude            # только разделы, где встречается "claude"
python domains.py check claude.ai x.ai       # разовая проверка
python domains.py check --failed             # только то, что не работало в прошлый раз
python domains.py check --html report.html   # автономный HTML-отчет с фильтрами и поиском
python domains.py check --json report.json   # полный отчет в JSON
python domains.py check --yes                # удалить NXDOMAIN, подтвержденные 2+ каналами
```

Домен проверяется по нескольким независимым каналам. Мертвым он считается, только когда каналы согласны между собой, поэтому один сбойный резолвер, провайдерская подмена DNS или временный сбой не приводят к удалению живого домена.

| Канал | Что дает |
|-------|----------|
| **DNS (UDP)** | Консенсус `1.1.1.1`, `8.8.8.8`, `9.9.9.9`. Для положительного ответа хватает одного резолвера, для NXDOMAIN нужно согласие минимум двух. Плюс NS зарегистрированного домена: по ним видна парковка и можно отличить "истек домен" от "удален только поддомен". |
| **DoH** | Все отрицательные ответы (NXDOMAIN, SERVFAIL, таймауты) перепроверяются через DNS-over-HTTPS (Cloudflare, Google). Провайдер не может подменить ответ внутри HTTPS. Если DoH нашел адреса, домен живой, а в заметке будет "вероятна подмена DNS". Если UDP/53 наружу закрыт, DoH автоматически становится основным каналом. Для NXDOMAIN-поддоменов дополнительно запрашивается CNAME: "висящий" CNAME на удаленный сервис показывается явно. |
| **RDAP** | Статус домена в реестре, независимо от DNS: не зарегистрирован, удаляется (redemption, pending delete), снят с DNS (client/server hold), срок истек. По умолчанию (`--rdap auto`) запрашивается только для подозрительных доменов, `--rdap all` проверяет все и предупреждает о регистрациях, истекающих в ближайшие 30 дней. Не у всех зон есть RDAP (например, `.ru`, `.io`, `.me`), тогда канал просто молчит. |
| **HTTPS/HTTP** | Настоящий TLS-запрос с проверкой сертификата, при ошибке сертификата повтор без проверки, затем HTTP:80. Ловит истекший сертификат, ответы Cloudflare 521/523/530 (фронт жив, сервиса за ним нет) и парковку (редирект на sedo.com, dan.com и т.п. или текст "domain is for sale"). Сертификат на чужое имя проблемой не считается: так часто выглядят защитные домены крупных компаний. |
| **История** | `.domains-state.json` помнит, сколько проверок подряд (в разные дни) домен не работает и с какого числа. Повтор проверки в тот же день серию не увеличивает. |

Перед проверкой каждый DNS-резолвер проходит самопроверку на контрольных доменах `example.com` и `iana.org` и на случайном несуществующем имени. Резолвер исключается, если не отвечает, подменяет NXDOMAIN (провайдерская реклама) или отдает fake-ip `198.18.0.0/15` (DNS перехватывает VPN-клиент или роутер). HTTPS-проба сначала подключается к `192.0.2.1` (RFC 5737, там никогда нет сервера) со случайным именем: если TLS прошел, трафик расшифровывает прокси, и проба отключается с предупреждением.

| Статус | Значение | Что делать |
|--------|----------|------------|
| работает | Есть адреса, сервер отвечает | - |
| DNS есть, сервер молчит | Имя резолвится, но 443 и 80 не отвечают. Часто это API, чат-эндпоинт или UDP-сервис. | Оставить |
| имя есть, адресов нет | NOERROR без A/AAAA. Нормально для зон вроде `oaiusercontent.com`. | Оставить |
| припаркован или брошен | NS у парковщика, страница парковки или RDAP: hold, удаление, истек срок | Проверить руками |
| служебный IP | Адрес `0.0.0.0`, `127.0.0.1`, `::` и т.п. | Проверить руками |
| сервис сломан (TLS/HTTP) | Истек сертификат или Cloudflare не видит origin | Проверить руками |
| сломан DNS | Все резолверы вернули SERVFAIL | Проверить руками |
| не существует | NXDOMAIN | Удалить |
| не удалось проверить | Таймауты даже после повтора | Повторить позже |

Для каждого проблемного домена выводятся причина, улики по каналам и список подтвердивших каналов:

```
list.txt:122     discordpartygames.com  [Discord]
                 домен не зарегистрирован (RDAP реестра)
                 DNS: NXDOMAIN от 3 из 3; DoH: NXDOMAIN от 2 из 2; RDAP discordpartygames.com: не зарегистрирован (RDAP реестра)
                 подтверждено: DNS, DoH, RDAP
```

После проверки программа спрашивает, что удалить: `y` удаляет все NXDOMAIN, `s` позволяет выбрать по одному, включая сомнительные, `n` ничего не удаляет. Без терминала удаление пропускается. `--yes` удаляет без вопросов, но только NXDOMAIN, подтвержденные минимум двумя каналами (история прошлых дней тоже считается каналом). Если DoH недоступен и NXDOMAIN видит только UDP, `--yes` оставит домен до повторной проверки в другой день. После удаления `list_2nd_level.txt` пересобирается.

Прочие опции: `--no-probe` (без HTTPS-пробы), `--no-doh`, `--doh URL`, `-r IP` или `-r https://...` (свои резолверы), `--rdap {auto,all,off}`, `--no-history`, `--timeout`, `-c` (параллельность).

Коды выхода: `0` - проблем нет, `1` - остались NXDOMAIN или SERVFAIL, `2` - ошибка запуска или провал самопроверки сети.

Полная проверка 532 доменов по всем каналам занимает около 16-18 секунд, из них HTTPS-проба около 12.

### keenetic - команды для роутера

```bash
python domains.py keenetic -i Wireguard0                  # команды в stdout
python domains.py keenetic -i Wireguard0 -o keenetic.txt  # в файл
python domains.py keenetic -i Wireguard0 --reject         # kill switch: блокировать, если VPN упал
```

Результат вставляется в CLI роутера (SSH/Telnet):

```
object-group fqdn vpn include claude.ai
object-group fqdn vpn include anthropic.com
...
dns-proxy route object-group vpn Wireguard0 auto
system configuration save
```

В одном списке доменов встроенных DNS-маршрутов Keenetic может быть не больше 300 записей. Если доменов больше, они поровну делятся на списки `vpn`, `vpn-2`, `vpn-3`, а каждому списку назначается свой маршрут. Имя интерфейса можно посмотреть командой `show interface` или в веб-интерфейсе.

Вместо команд домены из `list_2nd_level.txt` можно вставить вручную в веб-интерфейсе: "Сетевые правила" -> "Маршрутизация" -> вкладка "DNS-маршруты".

DNS-маршрутизация (и встроенная в Keenetic, и kvas) работает, только если клиенты получают DNS от роутера. Если на устройстве задан публичный DNS (например, 8.8.8.8) или включен DoH/DoT в браузере, роутер не видит запросы, и маршрут не срабатывает.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

CI (`.github/workflows/ci.yml`) на каждый push и PR запускает `lint --strict`, `build --check` и тесты на Python 3.10 и 3.13. Раз в неделю и вручную через "Run workflow" запускается полный `check`. Если появились мертвые домены, джоб падает, а отчеты JSON и HTML доступны в артефактах.

После правки `list.txt` запустите `python domains.py build` и закоммитьте оба файла, иначе CI упадет на `build --check`.

## Зависимости

| Пакет | Зачем |
|-------|-------|
| `aiodns` | Асинхронные DNS-запросы напрямую к выбранным резолверам (DoH, RDAP и HTTPS-проба работают на стандартной библиотеке) |
| `tldextract` | Public Suffix List (встроенный снимок, без сети) |
| `idna` | IDN -> punycode по UTS 46 |
